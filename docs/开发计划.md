## 1. 总体策略

1. **纵切优先**：每个里程碑以"可运行、可验证"为完成标准（DoD），不堆砌半成品模块
2. **后端先行，前端在 M3 后进场**：M3 结束时平台核心闭环（对话+引擎+能力）已可用（curl 验证），API 契约趋于稳定，前端再进场避免返工
3. **接口先冻结再开发**：M2 开工前冻结三处核心接口（LoopState / 钩子协议 / EngineBackend），这是模块详细设计 §5 的要求
4. **每个里程碑打 tag**：`v0.1-m1` … `v0.6-m6`，可回退、可复盘
5. **风险前置**：LangGraph 版本 API、MCP Server 兼容性两大外部风险在 M2/M3 最早期验证，不等开发到深处才踩

### M7a 任务架构（4 日）—— 主任务 + 子任务（已实施，见 ADR-23~28）

**动机**：M6 之前平台的心智模型是「一次对话 = 一个 run」。真实任务（如供应商报价对比）需要**多次交互 + 主线/支线并行**：报价单缺供应商名称、出现无法识别的工艺、识别到新供应商、内部数据有矛盾——这些都必须在执行中途向用户提问并等答复，而「谁在等、等到哪一步、整体还剩多少」必须对用户可见。

| 子阶段 | 内容 | 模块 | 工作量 |
|---|---|---|---|
| T1 任务模型 | 5 张表（task_types / task_type_steps / task_type_capabilities / tasks / task_steps）+ 迁移 + 「通用任务」seed + 全量 API（模板 CRUD、步骤 PUT 保序、能力绑定、实例、看板） | tasks + migrations | 1.5 日 |
| T2 引擎集成 | EngineBackend 六个任务钩子；任务卡注入 protected 区；planner 优先采用主线作计划（`plans.items` 带 `step_id`）；`ask_user`/`declare_subtask` 元工具；支线步骤级 interrupt + 答复回填（幂等键 `(run_id, name)`）；进度确定性重算 | engine + tasks | 1.5 日 |
| T3 归属分层 | 检索按「本主任务域 → 通用任务集 → 其它域」重排（候选放大 k×3 后截断），主线步骤 `capability_hint` 域内提权，装配 `source` 记录归属层 | discovery | 0.5 日 |
| T4 前端 | 左栏任务看板（分组/进度/角标/筛选/新建任务）、会话顶部任务条 + 子任务抽屉、支线澄清卡、新主任务软提示卡、任务模板管理页 | 前端 | 1.5 日 |

**DoD**：
1. 新建主任务「供应商报价对比」并发一条含报价单的消息 → 看板出现任务卡，进度条推进，planner 直接用模板主线（不自由拆解）
2. 触发支线（报价单缺供应商名称）→ 任务条出现 `awaiting_user` 子任务 + 澄清卡 → 答复后子任务 done、主流程继续；**重放不产生重复支线**
3. 同一会话问无关新话题 → 只出软提示卡（不落消息不建 run），两个选项都能走通
4. 任务模板页改步骤顺序/归属能力后新建任务，骨架与检索优先序随之变化；解绑能力后其归属自动落回「通用任务」
5. 未回归：M2~M6 全部既有验收项通过（`pytest` + 冒烟脚本）

## 5. 风险清单与前置验证

| 风险 | 影响 | 应对 | 验证时点 |
|---|---|---|---|
| LangGraph API 变动 | M2 返工 | 2a 即锁版本 + 写法验证，不裸奔到 2c | M2 开工首日 |

| 前端进度挤压后端 | 闭环延迟 | F5 可拆散后置；对话页（F2）优先保住核心体验 | 前端阶段 |
| 个人节奏中断 | 整体延期 | 每里程碑独立可用 + git tag，随时可停可续 | 全程 |
| M7a：新主任务误判/漏判 | 打断体验或任务串味 | 只做**软提示**不阻断；漏判时用户手动「新建任务」兜底；判定逻辑收在单一函数里便于替换 | M7a T2 完成后 |
| M7a：支线 interrupt 重放产生重复支线 | 看板出现重复子任务、进度算错 | 幂等键 `(run_id, name)` 先查后建 + 单测覆盖重放路径 | M7a T2 首日 |
| M7a：任务卡/进度与会话状态分裂 | 用户不信任看板 | 进度只有一个写入口（`recompute_progress`），看板/任务卡/事件三处同源；前端不本地估算 | M7a T2 + T4 |
| M7a：能力归属分层把有用能力挤出预算 | 任务反而做不成 | 候选先放大 k×3 再重排截断；归属是软约束不是白名单，通用任务集永远兜底 | M7a T3 |

### 7.2 与既有阶段的关系

- **不改 v0.x 已交付的行为契约**：M9 全部是"契约闭合 / 账实相符 / 一等化"类修复，对外接口只做**加法**

- **事件与失败码是冻结接口**：新增只能走受控扩展（后端枚举 + 前端 `eventTypes.ts` + 契约门测试三处同改），
