## 1. 设计原则（八条，按优先级）

| # | 原则 | 含义 |
|---|---|---|
| 1 | **过程可见性高于结果呈现** | Agent 思考、工具调用、计划进度实时可见——不可解释的 Agent 不可信任 |
| 2 | **状态永远诚实** | 索引中/连接不健康/预算吃紧如实展示，绝不静默失败或假装完成 |
| 3 | **注意力是稀缺资源** | 打断人的东西（确认卡片、通知）少而精、分级；Agent 能自己扛的别问人 |
| 4 | **密度优先于装饰** | 工作台风格：信息密度高、等宽字体辅助、留白克制、零纯装饰元素 |
| 5 | **一切可回放** | 每个 run 的完整事件轨迹可事后回放——出问题时人是复盘者不是猜谜者 |
| 6 | **渐进披露** | 默认展示结论，细节折叠（思考过程、工具参数、向量命中块） |
| 7 | **键盘可达** | 高频操作全有快捷键 + ⌘K 命令面板 |
| 8 | **全局状态常驻可见** | PG 连接 / 能力池健康 / 模型可用三盏状态灯常驻顶栏 |

## 2. 整体布局与菜单结构

### 2.1 布局骨架（桌面端三栏）

```
┌────────┬──────────────────────────────┬───────────────┐
│ 主导航  │  主内容区（随菜单切换）          │ 上下文面板      │
│ 可折叠  │                              │ （可折叠）      │
│ 图标+   │  消息流 / 表格 / 编辑器 / ...   │ 任务详情/事件流  │
│ 二级菜单 │                              │ /工具调用详情   │
└────────┴──────────────────────────────┴───────────────┘
   ▲ 顶栏：⌘K 搜索 │ 通知铃铛(徽标) │ 三盏状态灯 │ Agent 切换器
```

- 右侧上下文面板：主区看"什么"，右栏看"为什么/详情"——点任何 run、任何一次工具调用，详情在右栏展开，不打断主区
- 侧边栏展开态显示二级菜单（能力组下四个），收起态 hover 展开

### 2.2 菜单结构（8 个一级，能力组含 4 个二级）

```
💬 对话 Chat                     —— 任务工作台：左栏任务看板 + 右侧对话（一个主任务一个会话）
🗂 任务模板 TaskTypes            —— 主任务定义：子任务骨架 + 能力归属（M7a 新增）
📋 执行记录 Runs                 —— run 中心：进行中/历史/回放
📚 知识库 Knowledge              —— 目录树 + 文档 + 索引管道
🧩 能力 Capabilities
   ├─ MCP 服务                   —— 外部/社区 MCP Server 管理
   ├─ 工具 Tools                 —— 函数级能力（含内置元工具）
   ├─ 插件 Plugins               —— 自研 MCP Server（你开发的）
   └─ 技能 Skills                —— Skill 库 + 沉淀审核队列
🧠 记忆 Memory                   —— 平台记忆/日期记忆查看与手改
⏰ 自动化 Automation              —— 定时任务/闹钟
⚙️ 设置 Settings                 —— Agent 管理/模型接入/系统参数
```

**M7a 菜单调整**（任务架构）：原「任务」页拆为**任务模板**（定义层，人工维护）与**执行记录**（run 层，回放与排障）；主任务实例的"进行中/待确认/已完成"入口**上移到对话页左栏**——任务实例与会话一一对应，看板与工作台同屏才不来回跳页。`⌘K` 命令面板同步收录这两个入口。

**四类能力分设独立二级菜单的理由**：四者的管理对象、展示重点、操作集合差异显著（Server 看连接与健康、工具看签名与试用、插件看版本与来源、技能看内容与审核），Tab 切分会把异构信息挤进同一布局。二级菜单让每类有自己的页面骨架。

**归属可见性（M7a）**：能力列表页新增一列「归属主任务」（多标签，未归属的显示为「通用任务」），点击可跳到对应任务模板页的归属区编辑——能力的**装配优先序**在模板页定，能力本身的启停在能力页定，两件事分开不混。

**统一约定：四类能力的列表页均以"开关"为第一操作**——启用/停用直接决定该能力是否进入装配池（capability 级开关），是上下文预算控制的界面化。

## 3. 页面级设计

### 3.1 对话页（最重的页面，工作台风格）

```
┌──────────────────┬─────────────────────────────────┐
│ 任务看板（左栏）    │ 任务条：供应商报价对比 3/7 ▾ ▸子任务 │
│ [全部|进行中|待确认│ ├─────────────────────────────┤ │
│  已完成] [+新建]   │ │ 用户消息                      │ │
│ ▾ 供应商报价对比    │ ├─────────────────────────────┤ │
│   ● 报价单解析 3/7 │ │ ▸ 💭 思考过程（折叠，点击展开）  │ │
│   ● 报价对比       │ │ ▸ 📋 计划进度                 │ │
│   ⏸ 确认供应商名称  │ │   ☑ 报价单解析 ☑ 报价对比      │ │
│     （待答复·橙点） │ │   ◉ 生成对比报告（进行中）      │ │
│   ⚠ 供应商A·越界   │ │ ▸ 🔧 parse_quote · 3 结果      │ │
│ ▾ 合同审查         │ ├─────────────────────────────┤ │
│   ○ 条款抽取 0/4   │ │ Agent 回复（Markdown 渲染）    │ │
│ [+ 新建任务]       │ ├─────────────────────────────┤ │
│                    │ │ ┌─ 支线澄清卡 / 确认卡片 ──────┐ │
│                    │ │ │ 支线：确认供应商名称           │ │
│                    │ │ │ "报价单未给供应商名称，请确认"  │ │
│                    │ │ │ [自由文本输入________] [提交] │ │
│                    │ │ └─────────────────────────────┘ │
│                    │ │ 进行中控制条：[终止] 迭代7/25·12.4k│
│                    │ │ 输入框（Markdown 编辑模式）│发送 ↵ │
└──────────────────┴─────────────────────────────────┘
```

**关键交互细节**：

| 细节 | 做法 |
|---|---|
| 过程消息三折叠态 | 思考/工具调用默认折叠为单行摘要，点开展开——默认安静，需要时透明 |
| 计划进度常驻 | run 进行中时 todo 卡片钉在消息流内实时更新（plan_updated 事件） |
| 确认卡片非模态 | 出现在输入框上方而非全屏遮罩，可上翻记录再回来确认；dangerous 工具红色强调并展示完整将执行参数 |
| 预算指示 | 进行中 run 显示"迭代 N/max · token 消耗"——预算可视化让人敢于放手 |
| SSE 断线 | 顶部细横幅"连接中断，重连中…"，seq 续传自动恢复，无感知 |
| 会话切换不丢状态 | 切走再切回，进行中 run 状态保持 |
| 乐观更新 | 发送后消息立即可见，Agent 侧显示"装配上下文 → 检索能力 → 思考中"状态推进 |
| **左栏 = 任务看板**（M7a，取代原「会话列表」） | 一级按**任务模板分组**（可折叠），二级是任务实例卡片：任务名称、`Progress` 进度条（`3/7`）、状态徽标（进行中/已完成/失败/已取消）、待确认角标、越界角标；顶部 `Segmented` 筛选（全部/进行中/待确认/已完成）+ 搜索 + 「新建任务」。点卡片 = 进入该任务的会话；悬停出重命名/删除 |
| **任务条常驻会话顶部** | 当前主任务名 + 进度 + 状态 + 「子任务」抽屉 + 「上下文」入口；抽屉列出全部子任务（主线/支线标记、状态、来源 template/planner/agent_raised/user、已答复内容原文），可人工改状态或补一条子任务——**用户随时知道正在执行哪些任务、进度如何** |
| **支线澄清卡**（复用确认卡位置） | `confirmation_request(reason=subtask_clarification)` 时卡片标题写「支线：<子任务名>」并展示问题原文，输入为**自由文本**（非表单），提交后该子任务置 done、答复固化进任务条抽屉；不模态、可上翻记录 |
| **新主任务软提示卡** | 后端 `kind=task_switch_suggested` 时在输入框上方出现黄色卡：「这条消息看起来属于「合同审查」…建议新开会话」+ [新开会话并发送] [仍在本会话继续]；**软提示不阻断**，两个按钮都能走通（架构决策权交给用户） |
| **进度与后端同源** | 进度条数值只来自接口（`progress_done/progress_total`），前端不做任何本地估算；`plan_updated` 事件只触发刷新、不参与计算——避免「看板显示完成、任务卡还没完」的分裂 |
| 工作台风视觉 | 等宽字体用于工具名/参数/代码块；消息密度紧凑（行高 1.5）；过程痕迹与正文有明确视觉分层（左侧细线/底色区分） |

### 3.2 任务模板页（TaskTypes，M7a 新增）

```
┌──────────────┬──────────────────────────────────┐
│ 模板列表       │ 模板详情：供应商报价对比            │
│ 通用任务(锁定) │ 说明 [一句话描述________]           │
│ ▸供应商报价对比 │ Agent [默认▾]  状态[启用]  [保存]   │
│ ▸合同审查      │ ─ 子任务骨架（拖拽排序）──────────  │
│ [+ 新建模板]   │ ⠿ 1 报价单解析      主线  hint:—  │
│               │ ⠿ 2 报价对比        主线  hint:compare│
│               │ ⠿ 3 生成对比报告    主线  hint:—  │
│               │ ⠿ 4 确认供应商名称  支线·可选       │
│               │ [+ 添加子任务]  [保存顺序]         │
│               │ ─ 归属能力（M7a 归属层）──────────  │
│               │ [parse_quote ×] [compare ×] [+绑定]│
│               │ 未归属的能力自动落「通用任务」       │
└──────────────┴──────────────────────────────────┘
```

| 细节 | 做法 |
|---|---|
| 步骤编辑即保序 | 拖拽排序后提交整表（`PUT /task-types/{id}/steps` 全量替换），不做增量 diff——避免顺序错乱这一类隐蔽 bug |
| 通用任务不可删 | `kind=common` 的模板行只读（列表置顶 + 锁图标），它是所有未归属能力的兜底归属，也是历史会话的挂靠点 |
| 归属能力 = 装配优先序 | 绑定后该能力在本主任务的检索里置顶（域内优先），**不是**白名单；解绑最后一个业务模板会自动补绑「通用任务」，能力不会"消失"——界面用灰色说明文案写清这一点，避免误以为解绑 = 禁用 |
| 停用模板 | `enabled=false` 只是从「新建任务」弹窗消失；历史任务实例与任务卡不受影响（界面加副文案提示） |
| 与执行记录的分工 | 本页只管**定义**（模板/骨架/归属）；跑起来之后的实例、进度、回放全在对话页看板与执行记录页 |

### 3.3 执行记录页（原「任务页」）

- **三视图**：列表（默认，按状态/触发方式筛选）/ 看板（进行中、待确认、今日完成三列）/ 时间线（单 run 事件回放）
- **与任务架构的关系**：本页看的是 **run**（执行粒度），对话页看板看的是**主任务**（业务粒度）——一个主任务会对应多个 run。列表行显示所属主任务与子任务名（`task_id`/`step_id`），点进去能直接回到对应会话与看板卡片
- **回放模式**（本页灵魂）：选历史 run，右栏按 run_events 逐条回放，可调速——排查"它为什么这么做"
- 待确认任务醒目入口：红点 + 顶部摘要条"1 个任务等待你的确认"
- 行内快捷操作：恢复 / 终止 / 重跑

```

│ 目录树         │ 文档列表 + 拖拽上传区（常驻）  │

│  ├硬件规格 ▸   │ │ doc.pdf  🟢ready 328块│  │

```

- 目录树：右键菜单（重命名/移动/删除）、拖拽文档换目录
- 索引管道进度实时化：解析→切分→embedding 状态机可视化，失败显示原因 + 断点重试——**绝不静默失败**
- **检索测试器**（调试 RAG 刚需）：输入 query → 命中 chunks 及相似度分数、所属目录——调参全靠它
- sha256 去重提示："已存在相同文件，是否仍要上传？"

### 3.5 能力组（四个二级页面）

#### 3.5.1 MCP 服务页

管理对象：社区/第三方 MCP Server。

| 区块 | 内容 |
|---|---|
| 列表行 | 名称 + 描述｜**总开关**｜健康徽标（🟢🟡🔴，hover 看最近检查时间）｜版本｜风险等级标签｜transport 标签（stdio/http） |
| 展开行 | **工具清单**：该 Server 全部工具逐行列出（名称、描述摘要），**每个工具有独立开关**——工具级开关是上下文膨胀的最后闸门 |
| 详情抽屉 | launch 配置、env 变量（掩码）、test_info 用例、调用统计（次数/最近使用时间） |
| 注册向导 | 分步：基本信息 → transport/launch/env → 测试用例 → **运行测试**（逐条 ✓/✗ 与预期 diff）→ 启用 |
| 操作 | 试一下（发起迷你 run 直接调用）｜重新测试｜健康检查 |

#### 3.5.2 工具页

管理对象：函数级能力（builtin 内置元工具 + 自注册工具）。

| 区块 | 内容 |
|---|---|
| 分组 | 内置工具（load_skill / search_more_tools / search_knowledge…，只读展示，**开关可关**——例如关掉 search_more_tools 收紧 Agent 行为）/ 自定义工具（可编辑） |
| 列表行 | 名称｜签名摘要（等宽字体）｜来源标签（builtin/custom）｜**开关**｜风险等级 |
| 详情抽屉 | 完整 JSON Schema 签名、描述全文、test_info、最近调用记录 |
| 操作 | 试一下（填参数表单 → 执行 → 结果展示） |

#### 3.5.3 插件页

管理对象：自研 MCP Server（你在 IDE 写好注册进来的）。结构同 MCP 服务页，差异点：

| 差异 | 说明 |
|---|---|
| 来源信息 | 强调"你开发的"：源码路径/仓库链接、作者、构建信息 |
| 版本管理 | 版本历史列表（旧版本保留，当前生效版本高亮）；更新流程：上传新版本 → 冒烟测试 → 一键切换生效 |
| 与 MCP 页隔离的意义 | 第三方 Server 与自研插件的信任等级、变更频率、排障路径完全不同，混排会让自研插件的版本管理被淹没 |

#### 3.5.4 技能页

管理对象：SKILL.md 程序性知识。

| 区块 | 内容 |
|---|---|
| 视图切换 | **已入库技能** / **待审核草稿**（badge 显示数量，即技能工坊入口并入本页） |
| 列表行 | 技能名｜描述（yaml 头摘要）｜来源标签（forge 沉淀 / 手动创建）｜**开关**（关闭=退出语义检索池）｜版本｜相似技能提示 |
| 详情 | 左：SKILL.md 渲染预览（Markdown）；右：来源 run 执行轨迹摘要（可追溯） |
| 审核队列（草稿视图） | 草稿列表 + 触发原因标签（成功复盘/纠错沉淀）；详情左右分栏 diff：草稿全文 vs 已有相似技能差异；操作：批准（可先编辑）/ 驳回（填理由，理由回流为纠错记忆） |
| 手动新建 | Markdown 编辑器 + yaml 头表单（name/description/version）；实现：能力四页的注册/编辑统一走 CapFormDrawer（§4 右侧 Drawer 表单规范），手动新建时 yaml 头由名称/描述自动合成 |

### 3.6 记忆页

- 左：时间线（daily 按日期倒序）；顶部：平台记忆（platform）固定卡片
- 右：Markdown 编辑器直接改，保存提示"将影响下个 run 的注入"
- 每条记忆显示来源 run 链接（点击跳任务页回放）
- 搜索：全文 + 语义两种

### 3.7 自动化页

- **定时任务**：列表（cron 可视化描述"每天 09:00，下次：明天 09:00"+ 最近执行结果链接 + **开关**）；新建向导：选 Agent → cron 可视化编辑器（表达式输入为辅）→ input_template 预览
- **闹钟**：到点列表 + 新建（内容/时间/URL），纯提醒不执行业务
- 两区块顶部 Tab 切换

### 3.8 设置页

- **Agent 管理**：列表 + 编辑页——人格三件套三个 Markdown 编辑 Tab（SOUL / IDENTITY / MEMORY）+ 附加 system_prompt + 模型绑定下拉 + 能力绑定（pinned 多选列表 / semantic 池勾选）+ 预算配置（tool_budget、max_iterations、token 上限、超时）
- **模型接入**：Provider 表单（密钥输入后掩码）+ **用量图表**（按模型按天折线，日限额进度条）——花钱可见
- **系统参数**：上下文压缩阈值、默认 K 值、通知偏好等

## 4. 跨页面交互细节

| 细节 | 做法 |
|---|---|
| **右侧 Drawer 表单规范** | 实体的注册/编辑表单一律用右侧 Drawer（`placement="right"`，width 520-640，受控 open），不用 Modal；列表行详情查看同走 Drawer（先例：知识库文档详情 DocDetailDrawer、能力表单 CapFormDrawer）。轻量一次性确认（Popconfirm、审核意见等单字段输入）不受此限 |
| 任务详情右栏 | 默认收起，仅在具体事件时展开：发送消息自动关注新 run / 恢复待确认 run / 点击消息下方「任务详情」；顶栏图标可手动开关 |
| 通知中心 | 顶栏铃铛下拉：待确认 > 失败 > 完成 > 系统消息，分级排序；点击跳转对应详情 |
| 全局状态灯 | 顶栏三盏：PG 连接 / 能力池健康（N/M 在线）/ 模型可用；异常变黄红，点开明细 |
| ⌘K 命令面板 | 全局搜索（会话/任务/文档/能力/记忆）+ 快捷动作（新会话、上传文档、新建定时任务…） |
| 任务看板 ↔ 工作台联动 | 看板卡片选中态与当前会话强绑定（`tasks.conversation_id`）；从执行记录/通知中心点进某个 run，会自动定位并高亮其所属主任务卡片，任务条同步显示到对应子任务 |
| 新主任务只能从看板创建 | 「新建任务」= 选模板 + 首条消息（一次提交），前端不做「先建空会话再补任务」的两步操作——避免出现没有主任务的孤儿会话 |
| 待确认优先提醒 | 看板卡片橙点角标 + 任务条状态 + 输入框上方卡片三层一致；离开会话也不丢——待确认的 run 在通知中心置顶 |
| 空状态 | 每页引导式空状态（"注册你的第一个 MCP Server →"）；对话页因默认 Agent seed 开箱即用 |
| 加载策略 | 列表骨架屏、详情渐进加载，绝不整页 loading |
| 危险操作 | dangerous 级能力在确认卡片中红色强调 + 完整参数展示 |
| 深色模式 | 默认深色（工作台惯例），可切浅色 |
| 删除保护 | 主数据删除一律二次确认并提示引用关系（"该能力被 2 个 Agent 绑定"） |
