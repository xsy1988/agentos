## 2A. 任务架构数据（2 张表 + Worker 文件包，M7a → m8 文件化）

四层架构与存储的对应（m8 文件化后）：**L1 定义层** = Worker 文件包 `data/workers/<名>/<版本>/`（**不在 DB**）；**L2 实例层** = tasks + task_steps（运行期产生）；**L3 归属层** = 主 WORKER.md 头 `capabilities:` 工具引用清单（**不在 DB**）；**L4 会话层** = `tasks.conversation_id` 与 conversations 1:1。

> **m8 文件化**：原 `task_types` / `task_type_steps` / `task_type_capabilities` 三表已退役
> （迁移 `g8d9e0f1a2b3`，DB 模板 → 文件包导出脚本 `scripts/export_workers_to_files.py`）。
> 文件是唯一权威，读取统一经 `app/modules/workers/registry.py`（mtime 指纹缓存）；
> 「通用任务」兑底域改为内建常量 `COMMON_WORKER="__common__"`，不落库、无文件。

### 2A.1 Worker 定义层文件包（L1/L3，非 DB 表）

```text
data/workers/<Worker名>/              # 目录名 = 唯一标识（允许中文）
  manifest.yaml                       # {enabled: bool, active_version: "v2"|null(=最新)}
  v1/WORKER.md                        # 主任务：yaml 头（name/description/icon/color/
                                       #   capabilities 工具引用清单/references）+ playbook 正文
  v1/sub_workers/<子任务名>/WORKER.md # 子任务：yaml 头（seq/kind/optional/description/
                                       #   capability_hint）+ playbook 正文
  v1/references/*.md                  # 主任务引用文件（LLM 按需加载）
  v2/…                                # 每个版本一个文件夹，手动构建递增
```

版本纪律：只有生效版本可编辑，历史版本只读；编辑不产生新版本；演进手动「构建新版本」（复制生效目录 → vN+1）。任务创建时锁定当时的生效版本，全程读该版本文件；绑定版本目录被删时降级最新可用版本并只显示名称骨架。

### 2A.3 task_steps —— 子任务实例（L2）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | uuid PK | |
| task_id | uuid FK→tasks, ON DELETE CASCADE | |
| seq | int | 展示顺序；支线追加在末尾 |

**幂等键**：支线步骤按 `(run_id, name)` 复用——LangGraph 恢复会整节点重放，复用保证同一支线不重复创建（重复触发只把该行重置回 `awaiting_user`，不新增行）。

### 2A.4 能力归属（L3，非 DB 表）

归属改由主 WORKER.md 头 `capabilities:` 工具引用清单承载（能力名数组，`GET /workers/{name}/capabilities` 实时校验命中/缺失）。一个能力可被多个 Worker 引用。**应用层不变量**——未被任何启用 Worker 引用的能力自动落「通用任务」兑底域（registry 全量计算，非落表）；检索按「本主任务域 → 通用任务集 → 其它域」分层重排（ADR-28），归属只影响优先序，不会让能力"消失"。

| checkpoint_blobs | 状态序列化块 |
| checkpoint_writes | 待写入的状态更新 |

业务代码**只读不写**（如断点校验、状态展示）；由 `PostgresSaver.setup()` 在迁移时创建。`conversations.id` 与其 `thread_id` 一一对应。

---

## 4. 扩展与全局约定

| 项 | 约定 |
|---|---|
| 扩展 | `CREATE EXTENSION vector; pgcrypto;` |
| 主键 | 全部 uuid（除事件类流水表用 bigserial） |
| 时间 | 一律 timestamptz |
| 向量维度 | 部署时由配置决定（默认 1536）；capabilities / kb_chunks / memory_files 三处同维；**换 embedding 模型 = 重建这三处向量 + 迁移改列** |
| 删除策略 | 业务表对主数据 FK 用 ON DELETE RESTRICT（防误删被引用能力/模型）；文档、消息类用 CASCADE |
| 软删除 | 主数据用 status 字段，不做物理删除 |
