| 项 | 内容 |
|---|---|
| 文档版本 | v1.0 |

| 说明 | 字段类型为建议类型；`jsonb` 表示结构灵活字段；向量维度由部署时配置决定（默认 1536），更换 embedding 模型需迁移 + 重建索引 |

---

## 0. 数据分类总览

| 类别 | 定义 | 表数量 |
|---|---|---|
| **主数据** | 描述"系统里有什么"的相对稳定实体：人、Agent、模型、能力、知识库目录、定时规则 | 9 |
| **业务数据** | 运行时产生的"发生了什么"：会话、任务、事件、文档内容、记忆、记账、文件、通知 | 14 |
| **框架管理表** | LangGraph PostgresSaver 自动创建与维护，业务代码只读不写 | 3 |

**目录树示例**（对应产品知识 / 研发知识 / 生活知识）：

```
/产品知识        /研发知识        /生活知识
```

## 3. 框架管理表（3 张，LangGraph PostgresSaver 自动建）

| 表 | 说明 |
|---|---|
| checkpoints | 检查点主表（thread_id、checkpoint id、元数据） |
| checkpoint_blobs | 状态序列化块 |
| checkpoint_writes | 待写入的状态更新 |

业务代码**只读不写**（如断点校验、状态展示）；由 `PostgresSaver.setup()` 在迁移时创建。`conversations.id` 与其 `thread_id` 一一对应。

## 4. 扩展与全局约定

| 项 | 约定 |
|---|---|
| 扩展 | `CREATE EXTENSION vector; pgcrypto;` |
| 主键 | 全部 uuid（除事件类流水表用 bigserial） |
| 时间 | 一律 timestamptz |
| 向量维度 | 部署时由配置决定（默认 1536）；capabilities / kb_chunks / memory_files 三处同维；**换 embedding 模型 = 重建这三处向量 + 迁移改列** |
| 删除策略 | 业务表对主数据 FK 用 ON DELETE RESTRICT（防误删被引用能力/模型）；文档、消息类用 CASCADE |
| 软删除 | 主数据用 status 字段，不做物理删除 |

## 5. 核心关系图（文字版 ER）

```
agents ──1:N── capability_bindings ──N:1── capabilities ──1:N── capability_tools
agents ──1:N── runs ──1:N── run_events                    │
agents ──1:N── conversations ──1:N── messages             └─ embedding 索引
agents ──N:1── model_providers ──1:N── model_usage_daily

runs ──1:1── plans          runs ──1:N── skill_proposals（approve 后转 capabilities）
kb_folders ──1:N── kb_docs ──1:N── kb_chunks              （树：kb_folders.parent_id 自引用）
files ──1:N── file_refs ──N:1── (kb_docs | messages)
conversations.id ═══ LangGraph checkpoints.thread_id（框架表）
```
