# 运维手册

个人 Agent 平台的日常运维参考：启动停止、备份恢复、故障排查。

## 1. 日常启停（agentos CLI）

全局命令 `agentos`（软链至 `~/.local/bin/agentos`，指向 `bin/agentos`）：

```bash
agentos start     # 基础容器（pgvector + docling-serve）→ 后端 :8000 → 前端 :5173
agentos stop      # 停前后端进程 + docker compose stop
agentos restart   # stop + start
agentos status    # 查看三组服务的运行状态
agentos logs      # 跟随查看后端/前端日志（logs/ 下）
```

产物位置：日志与 pid 文件在项目 `logs/`（已 gitignore）。

## 2. 数据备份

### 2.1 自动备份（已配置 crontab）

每天 04:30 执行 `scripts/backup_db.sh`，产物写入项目 `backups/`（已 gitignore）：

- `agent_platform_YYYYMMDD_HHMMSS.sql.gz` — 数据库逻辑备份（pg_dump | gzip）
- `data_YYYYMMDD_HHMMSS.tar.gz` — `backend/data/`（知识库解析产物 markdown 正文，
  不在库里；恢复时缺它则知识库检索失效）

保留最近 14 份，超出自动轮转删除。日志：`logs/backup.log`。

手动触发 / 调整保留份数：

```bash
scripts/backup_db.sh        # 立即备份一份
scripts/backup_db.sh 7      # 保留 7 份
```

crontab 管理：`crontab -l` 查看，`crontab -e` 编辑。

### 2.2 恢复

```bash
# 1. 停后端（避免恢复期间有写入）
agentos stop

# 2. 恢复数据库（先建空库再导入；-c 丢弃恢复前残留连接）
docker exec -i agent-platform-db psql -U agent -d postgres \
  -c "SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE datname='agent_platform' AND pid<>pg_backend_pid();"
docker exec -i agent-platform-db dropdb -U agent agent_platform
docker exec -i agent-platform-db createdb -U agent agent_platform
gunzip -c backups/agent_platform_XXXXXXXX_XXXXXX.sql.gz | \
  docker exec -i agent-platform-db psql -U agent -d agent_platform

# 3. 恢复数据目录
tar -xzf backups/data_XXXXXXXX_XXXXXX.tar.gz -C backend/

# 4. 重启并验证
agentos start
curl -s localhost:8000/health
```

## 3. 故障排查

| 症状 | 排查 |
|---|---|
| `agentos start` 报 no configuration file provided | 从软链调用时路径解析失败；确认 `~/.local/bin/agentos` 指向仓库内 `bin/agentos` 且该文件未被移动 |
| 后端起不来 | `agentos logs` 看报错；常见：8000 被占用（`lsof -i:8000`）、数据库容器未就绪、`.env` 缺失 |
| 数据库连不上 | `docker ps` 确认 agent-platform-db 在运行；`docker exec agent-platform-db pg_isready -U agent` |
| 前端页面空白/接口 404 | 确认后端健康；浏览器控制台看是否跨域/路由问题；前端代理配置在 `frontend/vite.config.ts` |
| 模型调用失败 | run 详情（前端任务详情页或 `GET /api/v1/runs/{id}/events`）看 error 事件；常见：Kimi 凭据过期、上下文超限 |
| 知识库检索无结果 | 确认文档 status=ready；`backend/data/parse/{doc_id}.md` 存在；embedding 维度 1024 与 pgvector 列一致 |
| 定时任务不触发 | scheduler 的 timer 状态是否 enabled（paused 是主动暂停） |

## 4. 数据位置速查

| 数据 | 位置 |
|---|---|
| 业务数据（会话/消息/run/记账/知识库元数据） | PostgreSQL `agent_platform`（容器 agent-platform-db） |
| LangGraph checkpoint | 同库（langgraph schema） |
| 知识库解析产物正文 | `backend/data/parse/` |
| 上传原始文件 | `backend/data/uploads/` |
| 备份 | `backups/` |
| 运行日志 | `logs/` |

## 5. 例行检查（建议每周）

1. `crontab -l` 在位；`ls backups/` 有当日备份且大小正常（数据库 ~几十 MB）
2. `df -h` 磁盘余量（备份+日志+解析产物会缓慢增长）
3. 前端发一条闲聊 + 一条知识库查询，确认延迟与回答正常（黄金任务集见设计方案 §13.3）
